### 1.1 Arreglar Conectividad Vercel → Oracle Cloud

**Problema:** Los requests desde Vercel al backend dan timeout.

**Diagnóstico:**
```bash
# Verificar que el backend escucha en 0.0.0.0 (no solo localhost)
netstat -tlnp | grep 8000

# Verificar firewall de Oracle Cloud
sudo iptables -L -n

# Verificar Cloudflare Tunnel
docker logs cloudflared --tail 50
```

**Solución:**

#### Opción A: Configurar Cloudflare Tunnel para aceptar requests externos
Editar `docker-compose.yml`:
```yaml
cloudflared:
  image: cloudflare/cloudflared:latest
  command: tunnel --no-autoupdate run --token ${CLOUDFLARE_TUNNEL_TOKEN}
  environment:
    # ASEGURAR que el tunnel acepte conexiones
    - TUNNEL_METRICS=0.0.0.0:2000
```

#### Opción B: Exponer puerto directamente (menos seguro pero funcional)
Editar `docker-compose.yml`:
```yaml
gem-backend:
  ports:
    - "8000:8000"  # Ya existe, verificar que funciona
  extra_hosts:
    - "host.docker.internal:host-gateway"
```

#### Opción C: Configurar Vercel para usar HTTP (no HTTPS)
Editar `vercel.json`:
```json
{
  "rewrites": [
    {
      "source": "/api/:path*",
      "destination": "http://100.69.240.73:8000/api/:path*"
    }
  ]
}
```

### 1.3 Corregir Streaming del Engine

**Problema:** El stream se corta antes de enviar toda la respuesta.

**Archivo:** `local-watcher/engine_service.py`

**Solución:**
```python
async def execute_agent(self, agent_id: str, task: str, stream: bool = True):
    """Execute agent with proper stream handling."""
    # Agregar timeout handling
    # Aggar heartbeats al stream
    # Asegurar que el stream siempre cierre correctamente

    async def generate():
        try:
            async for event in self._execute_internal(agent_id, task):
                yield event
                # Force flush cada evento
                await asyncio.sleep(0)
        finally:
            # Siempre enviar evento de completion
            yield {"type": "done", "status": "completed"}

    return generate()
```
